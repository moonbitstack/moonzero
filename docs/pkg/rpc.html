01 / ROUTING

rpc

An RpcServer (config-driven) registers moonrpc Method handlers by gRPC path and dispatches unary calls, returning Unimplemented for unknown methods; RpcGroup registers a set of methods under one package.Service.

INTERFACE

type RpcHandler = (Bytes) -> Bytes

typeA unary RPC handler: it maps a request message's wire bytes to a response message's wire bytes (the application/grpc+proto payload, sans the length-prefix framing that @moonrpc.encode_message adds). Streaming handlers arrive with the h2 transport; this is the unary shape zRPC registers today.

type ServerStreamHandler = (Bytes) -> Array[Bytes]

typeA server-streaming handler: one request message in, an ordered sequence of response messages out (each framed as its own length-prefixed gRPC message). Mirrors pb.XxxServer server-streaming method, which writes to a grpc.ServerStream instead of returning one reply.

type ClientStreamHandler = (Array[Bytes]) -> Bytes

typeA client-streaming handler: every request message the client sends is collected, and after the client half-closes the handler returns one reply.

struct BidiStreamHandler

structA live bidirectional call: on_message fires once per request message and returns the replies to send right then, so responses interleave with requests; on_end runs after the client half-closes and returns the final replies before the grpc-status trailer. The moonzero-local mirror of @moonrpc.BidiHandler, so callers register bidi methods without naming the transport package.

type BidiStreamFactory = () -> BidiStreamHandler

typeA factory that mints one BidiStreamHandler per call, so each stream gets its own handler state.

struct RpcServer

structA zRPC server: config plus a registry mapping each method's gRPC :path (/package.Service/Method) to its handler. Handlers are registered via @moonrpc.Method descriptors — directly or through a RpcGroup — and dispatched by path, mirroring how registers service implementations on the underlying gRPC server. Unary, server-streaming, and client-streaming methods live in separate registries so one path resolves to exactly one cardinality.
