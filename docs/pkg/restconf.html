struct RestConf

structA REST service's configuration, embedding ServiceConf the way does. The name, bind address and request timeout live on that embedded config — host(), port() and timeout_ms() read them — and everything else here is RestConf's own. max_bytes is an Int where uses int64: it is compared against a request's Content-Length, and its own range= tag caps it at 32 MiB.

fn RestConf::new( service~ : ServiceConf = ServiceConf::new(), cert_file~ : String = "", key_file~ : String = "", verbose~ : Bool = false, max_conns~ : Int32 = 10000, max_bytes~ : Int32 = 1048576, cpu_threshold~ : Int64 = 900L, signature~ : SignatureConf = SignatureConf::new(), middlewares~ : MiddlewaresConf = MiddlewaresConf::new(), trace_ignore_paths~ : Array[String] = []) -> RestConf

fnA REST config with defaults: no TLS, not verbose, 10000 connections, a 1 MiB body cap, a 90% CPU shed threshold, and the full middleware chain.

fnThe address the service binds.

fnThe port the service binds.

fn RestConf::timeout_ms(self : RestConf) -> Int32

fnThe per-request timeout budget in milliseconds; 0 disables it.

fn RestConf::tls(self : RestConf) -> Bool

fnWhether a certificate and its key are both named. This library assembles an application, not a socket: the object it builds is handed to a host, and the host is what terminates TLS. These two paths are carried here so that host reads them from the same document as everything else — and a document that names only one of them is refused at load rather than leaving the service listening in the clear while its operator believes otherwise.

fn RestConf::from_yaml(src : String) -> RestConf raise Refused

fnLoad a RestConf from the YAML ships as etc/*.yaml. Keys are matched canonically, MOONZERO_* env variables override the file, and a value outside its options=/range= constraint is an error. Name and Port carry no default, exactly as in the reference: a rest service that does not say who it is or where to listen fails to load.

fn RestConf::from_json(src : String) -> RestConf raise Refused

fnLoad a RestConf from a JSON config string, with the same semantics as from_yaml.
