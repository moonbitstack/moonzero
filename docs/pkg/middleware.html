middleware

The onion layers that wrap the app: recovery (500 instead of a panic), cors (Access-Control-* headers), and request_id (x-request-id per request).

fn layer(l : &@mid.Layer) -> Middleware

fnAdapt a moonasgi mid.Layer into a moonzero Middleware. The two shapes are the same ASGI transformer, so this is the whole bridge — a layer written for moonasgi (cors, gzip, body_limit, server_errors, trusted_hosts, sessions, or a user's own) drops into a moonzero chain unchanged.

fn recovery(inner : @moonasgi.AsgiApp) -> @moonasgi.AsgiApp

fnRecovery middleware: run the wrapped application inside a try, and if it raises before any part of the response has gone out, emit a 500 Internal Server Error instead of letting the failure escape to the server. Once the response has started, a 500 can no longer be written — the status line is already on the wire — so the error is re-raised for the server to close the connection on. Answering late would append a second status to a response the client is already reading.

fn cors(conf : CorsConf) -> Middleware

fnCORS middleware: answer a preflight OPTIONS with 204 No Content and the policy headers, and stamp the same headers onto every other response. A request from an origin the policy does not allow is served without the Access-Control-* headers rather than refused — the browser is the one that enforces the policy, and a server-side refusal would break non-browser clients that never asked for CORS at all.

fn scope_header(scope : @moonasgi.Scope, name : String) -> String?

fnRead a header from an HTTP scope (lowercased-name convention); None for non-HTTP scopes or a missing header.

fn request_id(header~ : String = "x-request-id") -> Middleware

fnRequest-ID middleware: reuse an inbound x-request-id if the client sent one, otherwise mint a fresh monotonic id, and stamp it onto every response's HttpResponseStart. The counter is captured once per assembly, so ids stay unique across the requests this layer serves.
